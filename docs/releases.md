# Homelab releases

Stable numeric tags (`v1`, `v1.2`, `v1.2.3`) and published non-prerelease GitHub Releases run `homelab-release.yml`. The exact tagged commit must be reachable from main. The reusable test workflow tests that source before images publish. The workflow must exist at the tagged commit: old tags cannot gain it retroactively. Push a new stable tag containing these changes. CLI `release.yml` remains independent; releases created with GITHUB_TOKEN do not trigger another workflow, so tag pushes independently start the homelab publisher. GCP CD is manual-only and retains its production environment gate. Main pushes run CI only.

The publisher builds linux/amd64 images: `ghcr.io/michael-duren/rubber-duck` and `rubber-duck-runner-{go,python,c}`. Canonical `sha-<full source SHA>` images carry OCI source `https://github.com/michael-duren/rubber-duck` and revision labels. Duplicate events reuse verified manifests and original digests. Only explicit registry image absence permits a build; authentication, network, digest or label errors fail closed. Limit package writers so canonical tags cannot be overwritten. A partial publication retry reuses the completed images and builds missing ones.

Configure `HOME_INFRA_DISPATCH_TOKEN` with Actions write on `michael-duren/home-infra`. GITHUB_TOKEN publishes GHCR packages; application/database credentials never belong in Actions. One dispatch to `gitops-promote.yml`, ref `main`, supplies four string inputs: `app=rubber-duck`, `tag`, full lowercase `sha`, and `images` JSON mapping all four exact basenames to full `ghcr.io/michael-duren/<basename>@sha256:<digest>` references. No promotion happens until all four images verify. Infra separately needs `SOURCE_READ_TOKEN` with Contents read for private sources.

Concurrency serializes publishers but a pending Actions run can be canceled. Rerun canceled/failed runs with the same tag. Dispatch acceptance is not promotion success: inspect the home-infra run and gitops release ledger. Both app releases must seed the ledger before the first infra release creates a snapshot. Rollback is an explicit reviewed GitOps change; database rollback is separate. See home-infra `docs/gitops-promotion.md` and its activation runbook.

For `GC_GRADER=k8s`, set `GC_RUNNER_GO_IMAGE`, `GC_RUNNER_PYTHON_IMAGE`, `GC_RUNNER_C_IMAGE` to released digest references. These use IfNotPresent. `GC_RUNNER_PULL_SECRET=ghcr-pull` names a pre-existing Secret in the duck namespace, referenced by ephemeral grading Pods as well as the app. The kubelet pulls before sandbox networking applies; no registry credentials or service account token are mounted into learner containers. Empty image settings retain imported local `gc-runner-*` images with Never pull policy. Network denial, capabilities, CPU/memory limits and bounded tmpfs remain required.

Legacy `scripts/deploy-homelab.sh` and `make deploy-homelab` fail before credentials, imports or cluster access. Never apply main's UNRELEASED templates directly. Build locally with `docker build .` and `make runner-images`. Provision runtime and pull Secrets through the operator process, then adopt reviewed released snapshots with Argo. Real private pulls, all three languages and startup migrations require activation verification on the cluster.

Local checks: `python3 -m unittest discover -s tests -p test_release.py -v`, `make check`, and `go test -race ./internal/grader/k8sgrader`. No publication or live cluster access is needed for these checks.
